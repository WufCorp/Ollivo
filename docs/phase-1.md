# Фаза 1: каркас и установка — ход работ

Интерфейс: при первом запуске — мастер «Проверка → Папка → Сеть → Движок → Всё готово»,
потом вкладки «Компьютер» (железо, движки) и «Настройки» (прокси, HuggingFace).

План фазы — в [План](plan.md). Готово, когда на чистой машине установщик ставит программу,
скачивает llama.cpp и показывает «Всё готово».

## Структура репозитория
- `src/` — React + TypeScript. `api.ts` — типы и вызовы ядра (поля = serde-структуры Rust).
- `src-tauri/` — Tauri 2, Rust-ядро. Версия 0.0.1, идентификатор `ru.ollivo.app`,
  установщик NSIS `currentUser` (без прав администратора), языки RU/EN.
- `spikes/` — прототипы фазы 0.

## Rust-ядро
- `hardware.rs` — видеокарта через NVML (имя, память, CC, пропускная способность), драйвер,
  ОЗУ, несъёмные диски, `profile_risky` (кириллица/пробел в профиле).
  Сборка движков: CC ≥ 7.5 и драйвер ≥ CUDA 13 → `cuda13`; CC ≥ 5.0 и драйвер ≥ 12.4 → `cuda12`; иначе `vulkan`.
- `download.rs` — менеджер загрузок:
  - запрос первого байта без перенаправлений → размер, поддержка Range, SHA256 из `X-Linked-ETag` (HF);
  - куски по 8 МБ, 8 соединений; готовые куски — в `<файл>.part.json`, пауза = отмена, продолжение с того же места;
  - 5 повторов на кусок с растущей паузой; при ошибке — следующее зеркало; битый хеш → стираем и качаем с зеркала;
  - без Range — одно соединение без докачки.
- `manifest.rs` + `manifest/engines.json` — встроенный манифест движков (llama.cpp b11081: Vulkan / CUDA 12 / CUDA 13,
  SHA256 из дайджестов GitHub). `revision` — у кого больше, тот и главный (позже — свежий из S3).
  Сборка: первая из `prefer`, что идёт на этом железе (`Build::runs_on`); для чата — Vulkan.
- `engines.rs` — установка: архивы в `downloads\` → SHA256 → распаковка в `…-<сборка>.tmp` → переименование.
  Готовый движок: `engines\<id>\<версия>-<сборка>\` с меткой `ollivo.json`. Оборванная установка не выглядит готовой.
  При установке пишется `ollivo.files.json` — размер и SHA256 каждого файла.
  «Починить» (`repair`): удаляет остатки `*.tmp`, сверяет файлы со списком; битое или нет списка → переустановка.
  Перед починкой llama.cpp модель останавливается (файлы заняты).
- `net.rs` — прокси HTTP / SOCKS5 (`socks5h`: DNS через прокси), логин/пароль.
  Пароль — в диспетчере учётных данных Windows (крейт `keyring` 3), не в файле.
  «Проверить»: TCP до прокси → HuggingFace → GitHub, у каждого шага понятная ошибка.
  Без прокси — `no_proxy()`: системный прокси Windows не подхватываем, только настройки Ollivo.
- `settings.rs` — `%APPDATA%\ru.ollivo.app\settings.json`, запись через временный файл.
  Папка данных по умолчанию — диск с наибольшим свободным местом + `\Ollivo`.
- `hf.rs` — основной сайт / hf-mirror.com / своё зеркало; токен в диспетчере учётных данных.
  Токен уходит только на `huggingface.co` и хост зеркала (`Downloader::with_bearer`), не на CDN.
- `setup.rs` — проверки для мастера (видеокарта, драйвер ≥ CUDA 12.4, Vulkan, VC++, ОЗУ), выбор диска
  (`<диск>\Ollivo`, советуем самый свободный, < 20 ГБ — «мало места»), проверка записи, установка VC++.
- `process.rs` — запуск движков без консоли, лог `logs\<движок>.log` (+ `.prev.log`), сторож выхода,
  `wait_ready` по HTTP (при падении — последние 15 строк лога). Все движки в одном **Job Object
  с kill-on-close**: закрылась или упала Ollivo — Windows сама завершает движки.
- `llm.rs` — llama-server: `127.0.0.1:<свободный порт>`, `--no-webui`, `-c 8192`, `-ngl 999`;
  `/health` до 300 с, прогревочный запрос; `ask` без стриминга (чат со стримингом — фаза 2).
  Одна модель за раз: запуск новой останавливает старую. Загрузку можно отменить (`CancellationToken`):
  `llm_stop` и новый `llm_start` не ждут её конца; `llm_status` во время загрузки — `starting`.
- Команды: `hardware_info`, `settings_get/save`, `proxy_test`, `hf_check_token`, `setup_check`,
  `setup_choose_dir`, `setup_finish`, `vcredist_install`, `download_start`, `task_pause`,
  `engine_status`, `engine_install`, `engine_repair`, `llm_start/stop/status/ask` (событие `llm://state`). События `download://…`, `engine://progress|finished`.
- Тесты: 36 юнит-тестов (мини-сервер: Range, сбои, докачка, зеркало, пауза, прокси; установка из zip; настройки)
  + `--ignored`: `huggingface_real`, `llama_real`, `real_start_ask_stop`.

## Замеры
- HF, whisper `ggml-tiny.bin` 74 МБ: 1 поток — 0,6 МБ/с; 8 — 2,3 МБ/с; 16 — 2,7 МБ/с.
- ⚠️ По HTTP/2 reqwest пускает все потоки через одно соединение → те же 0,6 МБ/с.
  Клиент загрузок — только HTTP/1.1.
- Установка llama.cpp b11081 Vulkan (32 МБ) с GitHub: 18,7 с, `llama-server --version` → build 11081.
- Qwen2.5 0.5B Q4_K_M через менеджер процессов (Vulkan, GTX 1080): готов за 14,4 с, 158 ток/с, чтение вопроса 112 мс.

## Экран установки
`src/components/InstallScreen.tsx` — общий, в фазе 4 туда же пойдут Python, torch, ComfyUI (список `items`).
- До старта: «Скачаем 30 МБ — обычно это меньше минуты» (оценка по 2 МБ/с из замеров), [Начать] [Позже].
- Шаги ✓ / крутится / ждёт, общий прогресс, скорость, «осталось примерно N минут», подсказки раз в 7 с.
- Ошибки по `kind` из ядра (`net` / `disk` / `broken` / `other`): `net` → сами повторяем через 15 с или по событию `online`.
- Прогресс на кнопке в панели задач (`setProgressBar`, право `core:window:allow-set-progress-bar`).
- Проверено вживую на C:\Ollivo: старт → пауза → продолжение с 8 МБ → распаковка → готово.
  Не проверено вживую: обрыв сети.

## Обновления программы
Инструкция — `RELEASE.md` в репозитории. Раздача из S3: `prisma-prava/ollivo/updates/`,
`latest.json` (обычные) и `latest-beta.json` (ранние). Канал выбирается в настройках,
автопроверка выключается там же (выключено — ни одного запроса без просьбы).
- `update.rs` + команды `update_check` / `update_install`, событие `update://progress`.
  Прокси из настроек передаётся и в обновления.
- Ключ подписи: `~\.tauri\ollivo.key`, пароль — в диспетчере учётных данных Windows
  (`ollivo-updater-key`). Скрипт `scripts/publish-update.ps1` (`npm run publish-update`)
  читает пароль сам: собирает, подписывает, кладёт в S3 сначала установщик, потом описание.
- ⚠️ Потеря ключа = обновления не встанут ни у кого; нужна копия ключа.
- ✅ Цепочка проверена вживую: 0.0.1 нашла 0.0.2 в канале beta, скачала, поставила и перезапустилась.
  Плюс тест `published_update_real` (--ignored): описание из S3, установщик, подпись ключом программы
  и привязка подписи к версии.

## Находки
- Первые ~15 с загрузки с GitHub байтов нет (перенаправление и запрос размера) → на экране «Подключаюсь к серверу…».
- В песочнице Claude нельзя подключиться к localhost → `npm run tauri dev` запускать вне песочницы.
- Vite по умолчанию слушал только `::1`, а Tauri ждал IPv4 → dev-сервер и `devUrl` привязаны к `127.0.0.1`.
- ⚠️ llama.cpp (b11081) импортирует `msvcp140`, `vcruntime140`, `vcruntime140_1` и `vulkan-1.dll`.
  На чистой Windows VC++ может не быть → мастер ставит `aka.ms/vs/17/release/vc_redist.x64.exe /install /quiet /norestart`
  через UAC (коды 0, 3010, 1638 — успех). Позже: класть 3 DLL рядом с движком (app-local) — без UAC.
- Нет `vulkan-1.dll` → чат ставим на CUDA (`Engine::pick(.., vulkan, ..)`).
- hf-mirror.com отсюда отвечает 308 на huggingface.co (и файлы, и API) — зеркало работает не из всех стран.
  Поэтому токен разрешён и для huggingface.co, а проверка токена при таком перенаправлении спрашивает HF напрямую.
- Job Object проверен случайно: в тесте временный `Supervisor` сразу уничтожался, и Windows убивала
  процесс (код 0). Теперь это отдельный тест `dropping_supervisor_kills_engines`.
- ⚠️ `Set-Content -Encoding utf8` в Windows PowerShell пишет BOM, а JSON с BOM плагин updater
  не разбирает: в окне это выглядит как «не получилось связаться с сервером обновлений».
  Описание версии пишем `[IO.File]::WriteAllText` с `UTF8Encoding($false)`.
- ⚠️ Windows не хранит пустую переменную окружения: `$env:X = ''` удаляет её. Поэтому ключ
  без пароля не годится для автоматической сборки — tauri спрашивает пароль в консоли
  (перенаправление ввода не помогает, `dialoguer` читает консоль напрямую). Ключ сделан с паролем.
- keyring 4 сменил API → взят keyring 3 (`windows-native`).
