Прототипы лежат в `spikes/` репозитория (описание — `spikes/README.md`).

## model-probe — определение типа модели ✅
`spikes/model-probe` (Rust). Читает только заголовок файла, веса не нужны.
- **GGUF:** метаданные и список тензоров → архитектура, параметры, квантизация, слои, KV-головы, контекст, словарь, лицензия.
  LLM / mmproj (зрение) / диффузионные GGUF от city96 (flux, sdxl, wan…) различаются по `general.architecture`.
- **safetensors:** по именам тензоров: SD1.5 / SD2 / SDXL (размерность `attn2.to_k`), Flux dev/schnell (`guidance_in`),
  SD3, Wan (1.3B/5B/14B по `patch_embedding`), LTX-Video, HunyuanVideo, VAE (4 или 16 каналов), LoRA и её база,
  ControlNet, CLIP-L/G, T5, ESRGAN, LLM и Whisper в формате HF (нужна GGUF / ggml-версия).
- **Whisper ggml** (`lmgg`): размер модели по числу слоёв энкодера.
- **pickle** (`.ckpt/.pt`, zip `PK`): не открываем, предупреждаем.
- Для «полных» чекпойнтов показывает, что внутри (текстовый энкодер, VAE) и что ещё скачать (T5, CLIP, VAE).
- Проверено на заголовках 13 реальных файлов с HF (качались только первые байты через HTTP Range).

**Светофор:**
- LLM: веса + KV-кэш (f16) + ~0,4 ГБ CUDA + буфер логитов. Если не влезает — сколько слоёв (`-ngl`) на видеокарту при контексте 4096.
  Скорость ≈ 60% пропускной способности памяти / размер весов + 1,5 мс. Llama 3.1 8B Q4_K_M на GTX 1080 → 🟢, ~37 ток/с
  (похоже на реальность). При 4 ГБ видеопамяти → 🟡, 19/32 слоёв, ~9 ток/с.
- Картинки/видео: сама модель (без TE/VAE — ComfyUI грузит их по очереди) + память на вычисления по семейству.
  Коэффициенты грубые, **откалибровать на живом ComfyUI**.

## llama-server — чат ✅
Сборка b11081, тестовые файлы в `D:\gui_Ai_lab` (вне репозитория), клиент — `spikes/llama-server/chat.py`.

| Сборка | Размер (zip) | Распаковано | Qwen2.5 3B Q4_K_M: чтение запроса | генерация |
|---|---|---|---|---|
| CUDA 12.4 + cudart | 242 + 373 МБ | 1,1 ГБ | 1583 ток/с | 52 ток/с |
| CUDA 13.4 + cudart | 143 + 403 МБ | 0,7 ГБ | **падает: CUDA error на GTX 1080** | — |
| Vulkan | 30 МБ | 87 МБ | 675 ток/с | **81 ток/с** |

- **CUDA 13 на Pascal не работает — подтверждено.**
- На GTX 1080 Vulkan генерирует в 1,5 раза быстрее CUDA 12 (на 0,5B — в 2,5 раза), но читает длинный запрос в 2,3 раза медленнее.
  Flash attention разницы не дал.
- Vulkan в 20 раз меньше и не требует библиотек CUDA — работает и на AMD/Intel.
- У Vulkan первые 1–2 запроса медленные (~1,4 с до первого токена — компиляция шейдеров), дальше ~60 мс.
  CUDA — ~45 мс сразу. → после загрузки модели делать прогревочный запрос.
- Сервер стартует за 2–4,5 с (модель 0,5B), потоковый ответ через `/v1/chat/completions` работает.
- Видеопамять: model-probe предсказал 2,9 ГБ, реально 2,2–2,3 ГБ — запас ~0,6 ГБ, безопасно. Скорость предсказана точно (81 ток/с).
- Сборки llama.cpp выходят несколько раз в день → версия закрепляется в манифесте, обновляем после своей проверки.
- В curl из Git Bash кириллица портится (кодировка консоли) — тестировать через Python/Rust, не через curl.

**Предложение:** движок чата по умолчанию — Vulkan (маленький, везде работает, на Pascal быстрее).
CUDA-сборка — необязательный «ускоритель»: мастер ставит её, если короткий замер на этом ПК показал выигрыш.
Проверить на RTX: там CUDA, скорее всего, быстрее.

## Скачивание с HuggingFace
- Одно соединение: ~0,75 МБ/с. 8 параллельных HTTP Range: **5,7 МБ/с** (в 7,6 раза быстрее).
- SHA256 файла есть в заголовке ответа HF `X-Linked-ETag` — проверка целостности без отдельного манифеста.
- → менеджер загрузок в ядре: многопоточная докачка частями + проверка по `X-Linked-ETag` / SHA256 из манифеста.

## ComfyUI headless — картинка ✅
ComfyUI v0.37.0 из zip тега (49 МБ), без git. Клиент: `spikes/comfyui/txt2img.py` (API `/prompt` + `/history`).
- Первый старт 73 с (компиляция .pyc), повторный — **9 с**. → установщик прогревает (компилирует) заранее.
- SD 1.5 fp16, 512×512, 20 шагов: **9–11 с**, 2,6 ит/с на GTX 1080.
- **Пик видеопамяти +3,1 ГБ — прогноз model-probe 3,1 ГБ, совпал.**
- **Вопрос закрыт:** на Pascal лог пишет `model weight dtype torch.float16, manual cast: None` — веса fp16, удвоения нет.
- ComfyUI сам предупреждает: для RTX 20xx и новее нужен torch **cu130**. Итого по видеокартам:
  GTX 10xx → cu126, RTX → cu130. Манифест движков выбирает сборку по compute capability — и для llama.cpp, и для torch.
- Путь к моделям — через `--extra-model-paths-config` (наша папка `models\`), папка вывода — `--output-directory`.
- **SDXL 1.0, 1024×1024, 20 шагов: ~60 с** (2,8 с/шаг), пик +6,5 ГБ (7,9 из 8 ГБ) — работает впритык без замедления:
  ComfyUI (DynamicVRAM) подгружает недостающие веса по ходу. Первый прогон с загрузкой модели с диска — ~150 с.
  model-probe откалиброван: SDXL — 1,75 ГБ на вычисления; до +1 ГБ сверх свободной памяти — 🟢 «впритык».
- `nvidia-smi` под полной нагрузкой иногда не отвечает — в ядре память читать через NVML и терпеть ошибки.
- Лог ComfyUI в файл — только с `python -u`, иначе буфер теряется при остановке процесса.
- Одинаковый workflow с тем же seed ComfyUI не пересчитывает, а отдаёт из кэша за 0,4 с.
- Остановка: процесс по порту (в Git Bash `taskkill //IM python.exe` не сработал). В ядре — держать PID дочернего процесса.

## Находки и риски
- ⚠️ **Pascal (GTX 10xx) и CUDA 13.** Свежие сборки на CUDA 13 не поддерживают Maxwell/Pascal/Volta. Для CC < 7.5
  брать сборки llama.cpp/whisper.cpp на CUDA 12 (или Vulkan) и torch cu126 — проверено, работает.
  Для RTX ComfyUI требует torch cu130. Значит, в манифесте движков нужен выбор сборки по CC видеокарты.
- ✅ ComfyUI на GTX 10xx держит веса в fp16 — удвоения памяти нет (проверено на SD 1.5).
- Размеры «памяти разговора» большие: у Llama 3.1 8B на 8 ГБ свободно ~10k токенов контекста, не 128k.
  В простом режиме — 8192 по умолчанию, дальше по памяти.
- На тестовом ПК системный диск C: заполнен на 95% — реальный сценарий: мастер должен спрашивать диск и показывать место.
