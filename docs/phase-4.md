# Фаза 4: картинки → 0.5

План фазы — в [Плане](plan.md#фаза-4-картинки--версия-05-открытая-бета). Здесь — как сделано и почему.
Тестовый ПК: GTX 1080 8 ГБ, драйвер 582.66, ОЗУ 32 ГБ, папка программы `D:\Ollivo`.

## Установка по требованию — `pyenv.rs` (2026-09-27)

Картинкам нужны Python, torch и ComfyUI (~5 ГБ). Ставятся не в мастере, а когда человек
впервые идёт к картинкам.

Что откуда:
| Часть | Откуда | Как |
|---|---|---|
| uv 0.12.19 | GitHub, `engines.json` | обычный движок: SHA256, докачка, «Починить» |
| ComfyUI 0.37.0 | zip тега на GitHub, `engines.json` | обычный движок; архив стабилен (SHA256 совпал на двух скачиваниях) |
| Python 3.12.14 | `uv python install` | uv сам сверяет архив по своим хешам |
| torch 2.14.0, torchvision 0.29.0, torchaudio 2.11.0 | download.pytorch.org, `engines.json` → `python.torch` | наш загрузчик, 8 потоков, SHA256 из индекса PyTorch; GTX 10xx → cu126, RTX → cu130 |
| остальные пакеты ComfyUI | PyPI через uv | версии — на дату `exclude_newer` из манифеста |

Почему так:
- **Без venv.** venv хранит абсолютный путь к Python в `pyvenv.cfg`, а uv кладёт рядом
  junction `cpython-3.12-…` с абсолютным путём. Окружение фазы 0 после переименования
  `D:\gui_Ai_lab` → `D:\Ollivo` сломалось именно так — а у нас есть перенос папки программы
  на другой диск. Python из python-build-standalone находит библиотеки относительно `python.exe`,
  поэтому пакеты ставятся прямо в его копию `engines\python\<версия>-<сборка>\`.
  Пометку `EXTERNALLY-MANAGED` в ней удаляем: этот Python — только наш.
- **`--no-registry` и `--no-bin`.** Без них uv пишет Python в реестр Windows
  (`HKCU\Software\Python\Astral` — осталось от опыта фазы 0) и кладёт ярлык в `%USERPROFILE%\.local\bin`.
- **Без веб-интерфейса ComfyUI** (`comfyui-frontend-package`, шаблоны, встроенная документация,
  PyOpenGL, comfy-angle): это ~0,5 ГБ и большая часть времени установки в фазе 0. Без пакета
  интерфейса ComfyUI 0.37 выходит при старте, но с `--front-end-root` на папку с пустой
  страницей работает: SD 1.5 512² — 36 с с загрузкой модели, +3,1 ГБ видеопамяти (как в фазе 0).
  Ошибка «comfyui-workflow-templates is not installed» остаётся только в логе.
- **Всё временное — в папке программы**: `UV_CACHE_DIR`, `TEMP`, `TMP` → `downloads\`. На C: у людей
  бывает 5 ГБ свободных. Кэш uv после установки удаляется — он весит почти как окружение.
- **Чужие настройки не действуют**: из окружения uv убираются `UV_*`, `PIP_*`, `PYTHON*`,
  `VIRTUAL_ENV`, `CONDA*`, плюс `UV_NO_CONFIG`. Python запускается с `-E -s`: ни `PYTHONPATH`,
  ни пакеты из `%APPDATA%\Python` (там у кого-то свой torch) в наш Python не попадают.
- **Прокси** — из настроек Ollivo, переменными `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` для uv.
- `.pyc` компилируются при установке (`--compile-bytecode` и `compileall` для ComfyUI):
  без них первый запуск ComfyUI в фазе 0 шёл 73 с вместо 9.
- Метка `ollivo.json` путей не хранит: python, сборка, имена колёс torch и версия ComfyUI,
  под чей `requirements.txt` поставлены пакеты. Сменился torch — окружение собирается заново
  во временной папке; сменился только ComfyUI — пакеты доставляются в то же окружение.

Этапы для окна: `download` / `verify` / `unpack` (как у движков), дальше `python`, `packages`
(сколько осталось — заранее не известно), `warmup`. Лог шагов — `logs\images-install.log`.
Команды ядра: `images_status` (готово ли, сколько качать и места, есть ли NVIDIA) и `images_install`
(события `engine://progress` / `engine://finished` с id `images`).

- Окружение ставится сразу в итоговую папку, «готово» — метка, записанная последней. Сначала было
  как у движков: во временную папку и переименование в конце — на 4,8 ГБ свежих файлов Windows
  ответила «Отказано в доступе» (антивирус ещё проверял их), через пару минут то же переименование
  прошло. У движков переименование теперь повторяется до 2 минут (`engines::rename_dir`).
- Попутно: временная папка сборки звалась `with_extension("tmp")`, и у «3.12.14-cuda12» получалось
  «3.12.tmp» — версия после точки терялась. Теперь `…-cuda12.tmp` (`engines::tmp_sibling`).

Замер (`pyenv::tests::install_real`, колесо torch 2,6 ГБ подложено заранее — не качалось):
| Шаг | Время |
|---|---|
| uv и ComfyUI (31 МБ) | секунды |
| Python 3.12.14 | 22 с |
| пакеты: разрешение 72 пакетов / скачивание и распаковка / установка | 13 с / 3 мин 40 с / 1 мин 30 с |
| **всё** | **8 мин** (в фазе 0 — ~40 мин вместе с torch в один поток и интерфейсом ComfyUI) |
| повторный запуск: окружение уже есть, пакеты досверяются | 6–24 с |
Окружение — 4,7 ГБ (в фазе 0 venv был 5,2: минус веб-интерфейс). После установки в `downloads`
ничего не остаётся: кэш uv, TEMP и колёса удаляются.

## ComfyUI без окна — `comfy.rs` (2026-09-27)

- Запуск: `python -E -s -X utf8 -u main.py --listen 127.0.0.1 --port <свободный>
  --disable-auto-launch --disable-api-nodes --base-directory engines\comfyui\data --front-end-root …\data\noui
  --extra-model-paths-config …\data\model-paths.yaml --output-directory <папка>`, в Job Object,
  лог — `logs\comfyui.log`.
- `--base-directory`: настройки, база и временные файлы ComfyUI — в `engines\comfyui\data`, а не в папке
  сборки, которую сверяет «Починить» и заменяет обновление (папку без метки они не трогают). Рядом
  с движком — чтобы переезжала при переносе папки программы: переносятся только `models`, `engines`,
  `downloads`, `logs`. ComfyUI сам не создаёт `custom_nodes` в ней и падает — создаём при запуске.
- `--disable-api-nodes`: платные облачные узлы не грузим — без спроса в сеть не ходим.
- Модели не копируются: каждая папка с моделями записана в `model-paths.yaml` сразу во все виды
  (checkpoints, vae, loras…). Пути — строками JSON: правильный YAML, `\` и кириллица не ломаются.
- Задача: подписка на websocket **до** отправки в `/prompt` (иначе конец короткой задачи теряется),
  ход — сообщения `progress`, конец — `execution_success`, ошибка — `execution_error` с узлом и текстом.
  Отказ валидации (`node_errors`) — сразу понятной строкой. Остановка — `/interrupt`.
- Готовые файлы берём из `/history` (только `type: output` и только внутри папки вывода) прямо с диска,
  без `/view`: ComfyUI на этом же ПК. **Грабли:** «готово» по websocket приходит раньше, чем ComfyUI
  записывает итог в историю, — сразу после него `/history` бывает пуст. Ждём запись (до 30 с).
- Одинаковую задачу (тот же seed) ComfyUI не считает заново, а отдаёт прошлую картинку за 0 с —
  «Ещё вариант» должен менять seed.

Замер (`comfy::tests::txt2img_real`, SD 1.5 fp16, 512², 20 шагов): запуск ComfyUI 25–39 с,
первая картинка 10–11 с вместе с загрузкой модели, следующая 8,6 с. Ход по шагам приходит (20 из 20),
неверное имя модели — сразу строкой «CheckpointLoaderSimple: … not in [список моделей]».

## Раздел «Картинки» — `images.rs`, `Images.tsx` (2026-10-03)

Путь новичка: «Картинки» → (движок не стоит) экран установки → (моделей нет) подборка →
описание → «Нарисовать» → картинки в окне и в «Изображения\Ollivo».

**Что умеем.** Модели-чекпойнты Stable Diffusion одним файлом safetensors: SD 1.5, SD 2.x, SDXL
(`images::family`). ComfyUI грузит их одним узлом `CheckpointLoaderSimple`. Flux, SD 3.5, файл только
с UNet, `SDXL Refiner` — в списке «пока не запускаются» с причиной словами. Подборка (`images::PICKS`):
DreamShaper 8 (SD 1.5, 2,0 ГБ) и Juggernaut XL v9 (SDXL, 6,6 ГБ) — дообученные, а не базовые: на коротком
описании без «masterpiece, 8k» картинки заметно лучше. Хеши — из API HF, качаются обычной
`catalog_download` (путь теперь пускает и `.safetensors`). «Светофор» подборки — по видеопамяти:
SD 1.5 от 4 ГБ, SDXL от 8 ГБ (меньше — ComfyUI грузит частями, медленнее).

**Числа решает ядро** (`images::plan`), окно знает только «форму», «быстро ↔ качественно» и «сколько»:
| | SD 1.5 | SD 2.x | SDXL |
|---|---|---|---|
| квадрат / портрет / пейзаж | 512² / 512×768 / 768×512 | 768² / 640×896 / 896×640 | 1024² / 832×1216 / 1216×832 |
| CFG | 7 | 7 | 6 (выше пережигает цвета) |
Шаги — 15 / 25 / 35, сэмплер `dpmpp_2m` + `karras`. Размеры — родные для модели: на чужих SD рисует
двух голов. Отрицательное описание — общее, человек его не видит.

**Картинки по одной**, а не пачкой (`batch_size`): первая видна раньше, и SDXL на 8 ГБ (пик 6,5 ГБ на одну)
не упирается в память. Seed у каждой свой: одинаковую задачу ComfyUI отдаёт из кэша.

**Видеопамять — одна на двоих.** Перед генерацией модель чата «засыпает» так же, как после простоя
(`sleep_llm`), — окно разбудит её на следующем вопросе. Пока рисуется, запуск модели чата отказывает
понятной карточкой. При запуске модели чата ComfyUI получает `/free` — выгружает модели, но остаётся
запущенным: следующая картинка не ждёт запуска. После простоя (та же настройка, что у чата) ComfyUI
закрывается целиком — он держит модель ещё и в оперативной памяти. Отвечает чат — генерация не начнётся
(«дождитесь ответа»): обрывать чужой ответ молча нельзя.

**Время до старта — честное.** До первого прогона — по замерам GTX 1080 и пропускной способности памяти
видеокарты (вдвое за тензорные ядра RTX; ошибается в сторону «дольше»). Потом — замеры этого ПК
в `engines\comfyui\data\ollivo-speed.json`: скорость рисования по семействам (только картинки, где модель
уже в памяти), время запуска ComfyUI и скорость чтения модели (первая картинка минус рисование).
Запуск и чтение усредняются с прошлым замером: после перезагрузки они в разы дольше.

Замеры 2026-10-03, GTX 1080, отладочная сборка, NVMe:
| Что | Время |
|---|---|
| запуск ComfyUI первым после перезагрузки / из кэша Windows | ~2 мин / 26 с |
| чтение SD 1.5 (2,1 ГБ) с холодного диска | ~25 с |
| SD 1.5, «Быстро», 2 картинки 512², модель в памяти | 17 с (оценка по замеру — 17 с) |
| скорость SD 1.5 на `dpmpp_2m` | 2,14 с на шаг·Мп (с декодированием и связью) |
Первая генерация шла ~2,5 мин при оценке 58 с — поэтому запуск и чтение теперь тоже из замеров,
а без замера заложено 60 с и 100 МБ/с.

**Описание по-русски** модели SD не понимают (CLIP обучен на английском). Окно предупреждает до старта,
перевода пока нет — следующий шаг (моделью чата).

**Галерея** — `Изображения\Ollivo` (`picture_dir`), а не папка программы: там человек картинки и будет
искать, и они переживут удаление программы. Параметры в PNG пишет сам ComfyUI. Окно получает уменьшенные
копии (JPEG 320/768 точек) — PNG 1024² весит ~1,5 МБ. Открыть, показать в папке и превью — только для
файлов прямо в этой папке (`images::inside`).

**Отчёт о проблеме** берёт ещё `comfyui.log` и `images-install.log`, если они есть.

Проверено в окне (GTX 1080): раздел, оценка, предупреждение о русском, 2 + 2 + 1 картинка SD 1.5, ход
и «осталось», картинки появляются по одной, галерея, форма запоминается; модель чата Qwen2.5 3B уснула
перед генерацией и проснулась на вопросе, ComfyUI отдал память (4,1 ГБ занято на всё); экран подборки.
Не проверено в окне: экран установки (движок уже стоял), скачивание из подборки, «Остановить», SDXL,
нехватка памяти.
