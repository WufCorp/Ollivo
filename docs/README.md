# Ollivo — рабочая документация

Источник правды по проекту: решения, ход работ по фазам, замеры и находки.
Всё, что решено или проверено, записывается здесь, а не в переписке и не в личных заметках.
Обзор для пользователей — [README.md](../README.md), передача проекта целиком — [HANDOFF.md](../HANDOFF.md),
выпуск версий — [RELEASE.md](../RELEASE.md).

Сайт — ollivo.ru. Старое рабочее имя — `gui_Ai`; от него осталась только тестовая папка `D:\gui_Ai_lab` (вне репо).

## Суть
Десктоп-программа для запуска локальных открытых моделей (HuggingFace и т.п.) обычными людьми.
Установил → выбрал файл/модель → чат. Текст, картинки, видео, аудио в одном окне, голосовой ввод,
вложения. Два режима: «Простой» (всё настраивает сама) и «Профи» (все параметры, логи, терминал).
Конкуренты: ComfyUI (сложно), LM Studio / Jan / Ollama (только текст), Pinokio (установщик, не единый UI),
Stability Matrix, Fooocus, Msty.

## Архитектура
Фазы 0–2 закрыты, фаза 3 — голос и файлы ([Фаза 3](phase-3.md)) — собрана; следующая веха — 0.1, первая публичная сборка ([План](plan.md)). Репозиторий: `src/` — React, `src-tauri/` — Rust-ядро,
`spikes/` — прототипы фазы 0 ([Фаза 0](phase-0.md)). Общая схема (подробно — в [План](plan.md)):
- Оболочка: Tauri 2 + React + TypeScript.
- Ядро: Rust — загрузки, манифест версий, проверка железа (NVML), запуск движков. Данные — JSON-файлы (настройки, библиотека, разговоры).
- Движки: llama.cpp (текст/зрение), whisper.cpp (голос), ComfyUI headless (картинки/видео), TTS.
- Python (uv + встроенный 3.12) только для ComfyUI, ставится по требованию.
- Тип модели определяется по файлу (GGUF / safetensors) → выбор движка и «светофор».
- Обновления программы, манифест движков и зеркало — в S3 Timeweb, как в «buffer_pc» (личная заметка, вне репозитория).

## Решения
- Название: **Ollivo** (только английское), сайт ollivo.ru. Отброшены Stash, Domovoi, Lumaro и др. — конфликты с существующими продуктами (см. [Фаза 0](phase-0.md)).
- Идея: задачи вместо моделей («удалить фон», «озвучить текст») — для простого режима.
- ComfyUI использовать как скрытый движок, а не конкурировать с ним.
- MVP: только Windows + NVIDIA.
- Установщик маленький, всё докачивается само; системные Python/Git/CUDA не нужны (см. [Установка](install.md)).
- Компоненты ставятся по задаче: чат (llama.cpp) без Python, torch+ComfyUI — только для картинок/видео.
- Главный бэкенд — Rust-ядро Tauri, а не Python: логика установки должна работать до появления Python.
- Автообновление через Tauri updater + S3 Timeweb, как в ClipVault. Делается в фазе 1, а не в конце.
- Сборки движков выбираются по compute capability: CUDA 13 не поддерживает GTX 10xx и старше → для них CUDA 12.
- Кандидат: чат по умолчанию на Vulkan-сборке llama.cpp (30 МБ против ~600 МБ у CUDA), CUDA — опциональный ускоритель по замеру. Проверить на RTX.
- torch: GTX 10xx → cu126, RTX → cu130 (требование ComfyUI). Большие колёса качает наш менеджер загрузок, uv ставит из локальной папки; uv — с `--no-bin`.
- Менеджер загрузок качает в несколько потоков (с HF в 7,6 раза быстрее) и сверяет SHA256.
- Движки живут в Job Object с kill-on-close: после закрытия Ollivo не остаются висеть в памяти и видеопамяти.
- Ручных проверок в ВМ нет: всё, что можно, проверяют тесты — кириллица и пробелы в путях, работа без системного VC++ (`real_human_paths`). Ставить ВМ под каждый выпуск некому, а тест повторяется на каждом.
- Библиотеки VC++ (нужны llama.cpp и whisper.cpp) программа кладёт рядом с движком сама, а не ставит установщиком Microsoft: тот просит права администратора, и новичок на окне UAC пугается или отказывает. Копия — только если в системе библиотек нет или они старее: своя рядом с exe выигрывает и у более новой системной ([Веха 0.1](v0.1.md)). Раньше (фаза 1) их ставил мастер.
- Прокси (HTTP/SOCKS5) — во всех сетевых запросах ядра; пароли и токены — только в диспетчере учётных данных Windows.
- История разговоров — JSON-файл на разговор, поиск — перебором файлов, без SQLite: 23 МБ разговоров ищутся за 0,2 с ([Фаза 2](phase-2.md)).
- Пресеты вместо параметров: окно знает только названия ролей и манер, числа и промпты — в ядре (`presets.rs`). Направление перевода определяет ядро по буквам вопроса: маленькие модели условия в промпте не выполняют.
- Ошибки переводит ядро (`trouble.rs`), окно только рисует кнопки: так один и тот же сбой одинаково объяснён на всех экранах, а сырой текст не теряется — он под «Подробности».
- Токенов в окне нет: скорость — «слов в секунду» со сравнением с чтением, память разговора — в страницах. «40 ток/с» ничего не говорит человеку, а «быстрее, чем вы читаете» — говорит. Коэффициент — замер на русском тексте ([Фаза 2](phase-2.md)).
- CI собирает установщик без подписи обновлений: закрытый ключ только у владельца, в GitHub его не кладём. Выпуски подписываются при локальной сборке ([RELEASE.md](../RELEASE.md)).
- Документ хранится текстом в самой реплике разговора, а не ссылкой на файл: файл переедут или удалят, а разговор должен продолжаться с тем, что модель уже прочла ([Фаза 3](phase-3.md)).
- PDF разбирается в отдельном процессе (`ollivo.exe --pdf-text`): в release паника в разборщике закрыла бы всю программу (`panic = "abort"`).
- Документ длиннее памяти модели — предупреждаем до отправки и предлагаем приложить начало; поиск по большим документам — позже.
- Зрение (`mmproj`) не качается вместе с моделью, а предлагается, когда к модели без зрения приложили картинку: +530–900 МБ нужны не всем ([Фаза 3](phase-3.md)).
- Подходящее зрение выбирается по размерности (выход дополнения = ширина модели), а видит ли модель — спрашиваем у движка (`/props`): в общей папке могут лежать дополнения от разных моделей.
- whisper.cpp — только на процессоре, модель small: Vulkan-сборки нет, CUDA-архив без cuBLAS не работает; small на 12 ядрах в 3,8 раза быстрее реального времени, turbo для диктовки на процессоре слишком медленна ([Фаза 3](phase-3.md)).
- Распознавание речи ставится по первому нажатию микрофона, а не в мастере: нужно не всем, а это ~473 МБ.
- WebP и TIFF перекодирует ядро (крейт `image`), а не кодеки Windows: те для WebP, HEIC, AVIF ставятся из Store и есть не у всех. Без прозрачности — в JPG, а не PNG: картинка уходит движку с каждым вопросом, фото в PNG — 15–20 МБ. HEIC и AVIF — через ffmpeg, который нужен и для записей.
- ffmpeg ставится по требованию, как whisper, из 7z-архива (35 МБ против 115 у zip), и из архива берётся только `ffmpeg.exe`. Какой файл что требует, решает ядро, окно собирает одну карточку «докачать» на всё недостающее ([Фаза 3](phase-3.md)).
- Папка проекта: модель видит список файлов, а содержимое открывает сама инструментами — проект целиком в память локальной модели не влезает. Файл через «@» прикладывается целиком: так он дойдёт и до модели, не умеющей вызывать инструменты ([Фаза 3](phase-3.md)).
- Инструменты для папки — свои, в ядре, а не встроенные в llama-server (`--tools`): там есть запуск команд без спроса, а границы папки (в том числе через junction) проверяем сами.
- Работа с файлами папки — три режима, как в других программах: «Вручную» (каждое изменение с разрешения), «Авто» (модель меняет и удаляет сама), «План» (только план, ничего не меняет). Режим соблюдает ядро — в «Плане» у модели нет инструментов записи вовсе. Во всех режимах старый файл перед заменой и удалением копируется (30 дней), «Вернуть как было» — только если файл не меняли после модели: человек без технических знаний не должен потерять файл из-за ошибки модели. Запускать программы модель не может.
- Правда о действиях модели — из строк действий, а не из её слов: ответ «файл удалён» без настоящего удаления помечается предупреждением. Qwen2.5 3B так и соврала ([Фаза 3](phase-3.md)).
- Подписи кода (SmartScreen) пока нет — нет денег, бесплатно Microsoft не выдаёт. Обходимся инструкцией на сайте и VirusTotal.
- В 1.0 входит всё из [Плана](plan.md): картинки, задачи, видео и звук, «Профи». Урезать не стали — 1.0 должна быть тем, что обещано на сайте.
- Сборки выкладываются на GitHub с 0.1, а не после закрытого теста: матрицу железа одному не собрать. Поэтому кнопка «Сообщить о проблеме» переехала из фазы 8 в 0.1 — без неё публичные сборки не дадут отчётов.
- Отчёт собирает ядро, человек видит его целиком до отправки; переписки в нём нет, имя пользователя в путях заменено. В 0.1 — через форму issue GitHub и текстовый файл (не zip: его можно открыть Блокнотом и проверить); свой приёмник без аккаунта — решить к 0.5.
- Ошибки, которые видел человек, пишутся в `problems.log`, а не держатся в памяти: сообщить о проблеме часто решают уже после перезапуска ([Веха 0.1](v0.1.md)).
- Сборки и отчёты — в публичном `WufCorp/Ollivo` (Releases и Issues). LICENSE в репозитории нет — юридически это «все права защищены». Лицензию (OSI) добавить не позже 0.9: без неё не дадут бесплатную подпись кода SignPath Foundation, а заявку там рассматривают неделями. Какая лицензия — отдельное решение.
- История репозитория уже публичная, поэтому проверка её на секреты — сразу, а не перед выпуском. Проверена 2026-09-26 — чисто; с того же дня gitleaks проверяет каждый push в CI.
- Строки интерфейса выносятся в словарь в фазе 4, а не в 8: сейчас кода ~12 тыс. строк, к фазе 8 выносить пришлось бы вдвое больше.
- `recipes.json` подписывается: рецепт заставляет программу качать файлы, подменённый рецепт — это подменённые загрузки.
- Перенос папки программы — копированием целиком, и только потом удаление старого: вдвое больше места на время переноса, зато оборванный перенос ничего не ломает. Переносим только свои подпапки: в папке данных может лежать чужое.
- Модель после простоя выгружается, но не «останавливается», а спит: поле ввода остаётся, вопрос будит её сам. Иначе человек после перерыва увидел бы «запустите модель» и не понял, что случилось.
- Окно считаем враждебным: модель читает чужие документы, а в них может быть подсказка-ловушка. Поэтому строгий CSP (скрипты только свои, картинки только свои и `data:`, связь только с ядром), картинки из ответа — ссылками, у окна только те права, что оно зовёт само ([Веха 0.1](v0.1.md)).
- Манифест движков из S3 — только подписанный: он решает, какой exe скачать и запустить.
- Каталог моделей в S3 не выносим (2026-09-27): люди сами качают модели, какие хотят и откуда хотят, и подключают их к программе — файлом, из LM Studio / Ollama / ComfyUI или поиском по HuggingFace. Встроенной подборки хватает как стартовой, а вести свой каталог моделей — постоянная работа без пользы для человека.
- Знак — буква «О» облачком разговора с точкой-моделью, а не оливка: оливка объясняла название, но не говорила, что это за программа. Нарисован вектором (`src-tauri/icons/app-icon.svg`), для 16 и 24 px — свой, более жирный вариант (`app-icon-small.svg`): в обычном кольцо и хвостик пропадают. Цвета: плитка `#3F6115`, кольцо `#F2EFE2`, точка `#BCDA93`.
- Сайт — одностраничник в `site/` того же репозитория, выкладывается на GitHub Pages своим workflow: бесплатно, без сервера, обновляется тем же push. Обещаем на нём только то, что уже работает; остальное — отдельным блоком «Скоро».
- Модель не видит картинку — предлагаем конкретную замену (свою или из подборки под это железо) с кнопкой, а не «в каталог»: новичок не знает, какую там брать. «Красную» модель не предлагаем — скачать гигабайты ради «не хватит памяти» хуже, чем честно отправить в каталог.

## Как вести эту папку
- Решили что-то — строка в «Решения» здесь, с причиной. Причина важнее самого решения.
- Сделали что-то заметное — раздел в заметке своей фазы (как именно сделано и почему так),
  строка в «Лог» вида `- ГГГГ-ММ-ДД — что сделано` и галочка в «Осталось».
- Замеры и грабли записываются с числами и железом, на котором получены.
- Устаревшее исправляем или удаляем, а не копим рядом.
- Значения паролей, токенов и ключей сюда не попадают — только где они лежат и как называются.
