# Два языка: русский и английский

Сделано 2026-09-27: программа, сайт и GitHub — на русском и английском. В плане английский
стоял на 1.0 (фаза 8); перенесён вперёд по решению владельца — дешевле, пока строк сотни, а не тысячи.

## Программа

### Как устроено
- Строки пишутся **парой рядом**: в ядре `t!("Отмена", "Cancel")` и `tf!("{n} файлов", "{n} files")`
  (`src-tauri/src/i18n.rs`), в окне `t("Отмена", "Cancel")` и `pl(n, [...], [...])` (`src/i18n.ts`).
  Словаря с ключами нет. **Почему:** языков два, третьего не видно; пара на месте не даёт забыть
  перевод, при правке видны обе строки, а в React и Rust устроено одинаково. Понадобится третий
  язык — тогда переходить на словарь.
- Язык хранит ядро: `settings.language` (`ru` | `en`). Окно берёт его при запуске (`setLang`)
  и меняет командой `language_set` — сразу, без «Сохранить»: окно на непонятном языке — тупик.
  Названия языков в списке — каждый на своём («Русский», «English»), подпись «Язык · Language».
- Первый запуск: языка в файле нет → у того, кто уже пользовался программой (`setup_done`), русский
  (до 0.3 она была только русской); у нового — язык Windows (`GetUserDefaultUILanguage`): русский
  для ru, uk, be, kk, иначе английский. В мастере первого запуска переключатель стоит первым.
- Язык в ядре — глобальный (`i18n::set`), а не параметр каждой функции: ошибки рождаются глубоко,
  протаскивать язык через все вызовы ради двух значений — шум. Тестам — `i18n::test_en()`,
  язык на поток: тесты идут параллельно.
- На языке окна и то, что уходит **модели**: системные промпты ролей, описания инструментов папки
  проекта, «справка от программы». Спрашивающему по-английски русский промпт тянул бы ответ на русский.
  Переводчик в обоих языках — «русский → английский, остальное → русский»: пара та же.
- Что написано при чтении файла модели (`ModelInfo`: заметки, семейство) — кешируется в `models.json`
  с полем `lang`; язык сменили — заголовок перечитывается.
- Каталог: `about_en`, `tags_en` в `manifest/catalog.json`; тест требует их у каждой модели.
- Описание обновления одно на все программы: `-Notes` и `-NotesEn` у `publish-update.ps1` уходят
  в `latest.json` через строку `---`, программа показывает свою часть (`update::notes_for_lang`).
- Слова и страницы: по-английски 1,2 токена на слово (замер фазы 2), страница — 360 токенов
  (~300 слов по 6 знаков; знаков на токен по-английски не замеряли). Считаем по языку окна.

### Грабли
- Служебные строки, по которым ядро и окно что-то узнают, **не переводить**: `отменено`
  (`llm::CANCELLED`), `no-engine` (`trouble::NO_ENGINE`). Сырые ошибки, которые разбирает
  `trouble.rs`, узнаются на обоих языках: язык могли сменить, пока модель грузилась.
- Начала строк «занято будет ~ / will use ~», «нужно ~ / need ~» (`Fit.tsx`) и «пишет / writes»
  (`Chat.tsx`) окно ищет в ответе ядра — меняя текст в `probe.rs`, поправить и там.
- `thiserror` убран: текст ошибки зависит от языка, поэтому `Display` написан вручную.
- Константы со строками на уровне модуля в TS не работают — вычисляются один раз при загрузке.
  Всё, что показывается, — функциями (`tabName()`, `fileModes()`, `panelTabs()`).
- Установщик NSIS был двуязычным и раньше (`bundle.windows.nsis.languages`).

### Проверено
- `cargo test` — 144 теста, среди них английские: `i18n`, `trouble::english`, `presets::english_*`,
  `probe::english_words_and_pages`, `update::notes_in_window_language`.
- В окне (`tauri dev`, 2026-09-27): переключение в настройках сразу меняет панель, строку состояния
  и страницу; «Модели» (оценка ядра) и «Каталог» (описания, варианты, светофор) — по-английски; обратно
  на русский — тоже сразу.
- **В окне не смотрели:** мастер первого запуска с переключателем, чат с моделью по-английски, отчёт.

## Сайт
- `site/index.html` — русская, `site/en/index.html` — английская. Стили и скрипт вынесены в общие
  `site/style.css` и `site/site.js`, чтобы страницы не разошлись в оформлении.
- Переключатель RU/EN в шапке; выбор запоминается (`localStorage`, `ollivo-lang`). Первый заход
  на русскую страницу из браузера не на ru/uk/be/kk — сразу на английскую; роботов не уводим, чтобы
  русская страница индексировалась русской. Программа открывает сайт с `?lang=` — это тоже выбор.
- `hreflang` на обеих страницах. Блок «Поддержать» на обеих собирает `make-support.mjs`.
- Проверено в браузере: оба языка, переключатель туда и обратно, якорь `#support` переживает
  переход, 375 px без горизонтальной прокрутки.

## GitHub
У GitHub нет переключателя языка — принято держать файлы рядом со ссылками наверху.
- `README.md` — английский (его GitHub показывает всем и индексируют поисковики), `README.ru.md` — русский;
  в первой строке каждого — ссылка на другой.
- `DONATE.md` — английский (на него ведёт «Sponsor»), `DONATE.ru.md` — русский; оба собирает
  `make-support.mjs` из `support.json` (там `network_en`, `note_en`), кнопки — `boosty-en.svg`, `yoomoney-en.svg`.
- Формы issue и описания меток — на двух языках в одном файле («Что случилось / What happened»);
  имена меток прежние, русские, — их ставит программа.
- Выпуск: `release-notes/<версия>.en.md` рядом с русским, `release.yml` без него не соберёт выпуск.
- Описание репозитория («About») задаётся в настройках GitHub — из кода не меняется.
- Документация в `docs/`, `HANDOFF.md`, комментарии и коммиты — только по-русски.
