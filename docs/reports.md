# Отзывы и отчёты людей

Что пришло после публичных выпусков, что из этого сделано и что ждёт решения.
Матрица железа по отчётам — пока здесь же, отдельный `hardware.md` — когда отчётов станет больше.

## 2026-10-03: первый разбор (отзыв из чата + issues #1–#3)

### Исправлено

- **Чат терял вопросы.** При переходе на другую вкладку во время ответа `Chat` размонтировался,
  а разговор сохранялся только после конца ответа. Вернувшись, окно читало старую версию с диска:
  вопроса нет, хвост ответа дописывался к прошлому ответу и никуда не сохранялся — после перезагрузки
  пропадал и он. Теперь чат не размонтируется (скрыт через `display: none`, перетаскивание файлов
  на других вкладках игнорирует), вопрос пишется на диск сразу при отправке, записи идут цепочкой
  (`saving` в `Chat.tsx`: вторая ждёт номер, выданный первой, — иначе новых разговоров было бы два).
  Сменили разговор посреди ответа — недописанное сохраняется в тот разговор, модель останавливается,
  хвост отбрасывается.
- **Tesla P4 не использовалась** (Hyper-V, DDA). Серверные карты под Windows по умолчанию работают
  в режиме TCC (или MCDM) — без графики. NVML карту видит, поэтому «Компьютер» показывал всё верно,
  а Vulkan — нет: движок молча считал на процессоре. Теперь ядро читает режим драйвера
  (`Gpu.compute_only`, `nvmlDeviceGetDriverModel`), для такой карты Vulkan не выбирается — ставится CUDA 12.
  Уже стоит только Vulkan — при запуске модели «Движок чата не видит эту видеокарту» с кнопкой,
  карточка движка предлагает поставить нужную сборку. В отчёте — пометка «без графики (TCC)».
- **Запасная сборка CUDA.** Раньше поставить CUDA было нельзя вообще: окно всегда ставило сборку
  по умолчанию (Vulkan). Теперь в карточке движка на «Компьютере» — «Поставить сборку CUDA 12 (≈ 645 МБ)»,
  если она пойдёт на этом ПК. Из установленных запускается CUDA (`engines::best`): её ставят нарочно.
- **Падение 0xC0000005 при запуске** (issues #1, #2: GTX 1070, драйвер 582.66, Vulkan b11081, падает через
  0,14 с — ещё до модели). Причина неизвестна: в отчёте лог обрезан. Теперь вместо «Попробуйте ещё раз» —
  «Движок чата упал при запуске»: обновить драйвер, не помогло — поставить сборку CUDA.
- **NUL-байт в `engines.rs`** (тест `tmp_keeps_whole_version`): `comfyui\0.37.0` — бэкслэш съело
  экранирование при записи файла, получился настоящий NUL; файл стал «бинарным» для git и grep.
  Там же в `docs/README.md` и `HANDOFF.md` было `target<TAB>est-tmp` вместо `target\test-tmp`.
  Грабля: в heredoc у инструмента правки `\\` превращается в `\`, а `\t` — в табуляцию.

Собрано, тесты проходят. Потеря вопросов при смене вкладки **проверена в окне** (второй заход):
вопрос, уход на «Компьютер», возврат — ответ дошёл; второй вопрос в том же разговоре виден и сохранён,
на диске один файл с четырьмя репликами. Карточка движка и TCC в окне не проверены (нет такой карты).

### Неверно в отзыве

- «Движки качаются с S3 автора». Нет: llama.cpp, whisper.cpp, ffmpeg, uv и ComfyUI качаются
  с официальных выпусков на GitHub, SHA256 зашит в программу (`manifest/engines.json`).
  S3 — только обновления самой программы, и они подписаны. Манифест движков из S3 не подключён
  (`newest()` — `dead_code`). Когда подключим — подписывать тем же ключом, что обновления,
  иначе S3 станет единой точкой отказа.

### Сделано по итогам разбора (2026-10-03, второй заход)

- **Удаление в «Авто» — всегда с вопросом.** Создание и правки «Авто» делает сам, а удалить файл
  спрашивает, как в «Вручную» (`Tools::save`: `mode == Ask || content.is_none()`). Документ в папке
  может подсказать модели что-то удалить, а граница папки этого не остановит. Модели так и сказано
  в промпте; тест `modes_auto_and_plan` проверяет, что спросили только про удаление.
- **Ключ API у llama-server — всегда.** Случайный на каждый запуск (`llm::new_key`, 32 байта
  из генератора Windows), все запросы ядра — с ним (`llm::Endpoint`). Проверено на настоящем движке:
  без ключа — 401 (`real_start_ask_stop`); стриминг, папка проекта, переполнение памяти — с ключом.
- **Модель для других программ** — «Настройки → Для других программ». Переключатель действует сразу
  (`share_set`, мимо «Сохранить»): постоянный порт (по умолчанию 11500 — рядом с Ollama 11434, но не он),
  постоянный ключ в диспетчере учётных данных (`share-key`), «Копировать», «Новый ключ», инструкция
  для SillyTavern, qwen-code (строка PowerShell с адресом и ключом) и прочих. Только 127.0.0.1.
  Пока доступ открыт, модель не выгружается при простое — чужих вопросов Ollivo не видит.
  Режима «Профи» пока нет, поэтому раздел — в обычных настройках, но выключен по умолчанию.
  Проверено в окне: с ключом из кнопки «Копировать» модель ответила на `127.0.0.1:11500`, без ключа — 401.
- **Модель на чужом сервере** — «Модели → Модель на другом компьютере или сервере…» (спрятано за
  ссылкой). Адрес приводится к адресу API (`llm::api_url`: без пути — `/v1`), «Проверить» показывает
  список моделей сервера, «Подключить» заменяет свою модель (`remote_connect`). Ключ — в диспетчере
  учётных данных (`remote-key`). Чужому серверу не шлём поля llama-server (`grammar`,
  `chat_template_kwargs`, `timings_per_token`): API OpenAI отказывает во всём запросе из-за незнакомого
  поля. Скорость считаем сами, если сервер её не прислал. Ошибки — свои (`trouble::remote_chat`):
  «не отвечает», «не принял ключ», «нет модели». Картинки и папку разрешаем: что умеет чужая модель,
  сервер не говорит; не умеет — откажет, и человек увидит почему. Проверено в окне на отдельном
  llama-server с ключом: неверный ключ — «Сервер не принял ключ», подключение, ответ в чате, «Отключить».
- **Ограничение скорости загрузок** (#2) — «Настройки → Сеть»: без ограничения / 1–25 МБ/с (рядом —
  Мбит/с, тарифы пишут в них). Один предел на всю программу (`download::set_limit`, «ведро» с долгом):
  все соединения и загрузки делят его, смена действует и на идущие. Запас после затишья — полсекунды.
  Замер (`speed_limit_real`): 1 МБ восемью соединениями при пределе 250 КБ/с — 4,0 с.
  Не ограничивается: пакеты Python для картинок — их качает uv сам.

### Ждёт решения

- **Лицензия.** Её нет — юридически «все права защищены». Нужна до SignPath (бесплатная подпись
  для открытых проектов) — раньше планировали к 0.9. Вопрос не «когда», а «какая»: MIT/Apache-2.0
  (просто, разрешает всё) или GPL-3.0/AGPL (форки обязаны оставаться открытыми).
- **Доступ из локальной сети** к модели для других программ — пока только 127.0.0.1.
- **Гайд на сайте** про SillyTavern и qwen-code — в программе он есть, на сайте нет.
- **Портативный режим** (issue #3) — всё в одной папке рядом с программой (настройки, разговоры,
  модели), без `%APPDATA%` и реестра. Tauri пишет в `%APPDATA%` и `%LOCALAPPDATA%` (WebView2) сам —
  надо проверить, что из этого переносится.
- **Почта для отзывов** — у кого нет GitHub; сейчас есть Telegram и MAX.
- **Подпись кода.** Без неё SmartScreen учит жать «Всё равно выполнить». SignPath бесплатен
  для открытых проектов — нужна лицензия.

### Не ошибка

- **«Видит 40 потоков из 80».** llama.cpp по умолчанию берёт столько потоков, сколько физических ядер:
  на процессоре упирается в скорость памяти, а не в ядра, и второй поток на ядре не ускоряет.
  Половина логических процессоров в диспетчере задач — это норма. Настоящая проблема была в видеокарте.
