# Выпуск версии Ollivo

Обновления раздаются из S3 (Timeweb), бакет `prisma-prava`, префикс `ollivo/updates`.
Программа проверяет `latest.json` (обычные версии) или `latest-beta.json` (ранние)
и ставит обновление, только если подпись сходится с ключом в `tauri.conf.json`.

## Что нужно один раз

- **Ключ подписи** — `~\.tauri\ollivo.key`, вне репозитория. Пароль к нему — в диспетчере учётных
  данных Windows под именем `ollivo-updater-key`; скрипт читает его сам.
  Публичная половина зашита в `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`.
  Потеряете ключ — обновления перестанут ставиться у всех, кто уже поставил программу:
  придётся выпускать новую версию с новым ключом и просить переустановить вручную.
  Сделайте копию ключа в надёжном месте.
- **Доступ к S3** — профиль AWS CLI `timeweb` (`~/.aws/credentials`), регион `ru-1`,
  endpoint `https://s3.twcstorage.ru`. В репозитории ключей нет.

## Выпуск

1. Поднять версию в трёх местах: `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`.
   Скрипт не даст опубликовать, если они разошлись.
2. Проверить сборку и подпись, ничего не публикуя:

```bash
powershell -File scripts/publish-update.ps1 -DryRun -Notes "Что нового"
```

3. Опубликовать. Сначала для ранних версий:

```bash
powershell -File scripts/publish-update.ps1 -Channel beta -Notes "Что нового"
```

4. Убедиться, что у бета-пользователей обновление встало, и выпустить для всех:

```bash
powershell -File scripts/publish-update.ps1 -SkipBuild -Notes "Что нового"
```

`-SkipBuild` берёт уже собранный установщик, поэтому в оба канала уходит один и тот же файл.
Подпись при этом делается заново: установщик мог быть пересобран без ключа, а старый `.sig`
рядом остаётся от прошлой сборки.

## Что делает скрипт

- собирает установщик NSIS и `.sig` рядом с ним (`bundle.createUpdaterArtifacts`);
- составляет `latest.json` с версией, описанием, датой, подписью и ссылкой;
- кладёт в S3 сначала установщик, потом описание — чтобы никому не предложили
  обновление, которое ещё не загрузилось;
- установщик лежит под именем с версией, поэтому прошлые версии остаются доступны.

## Как это выглядит у пользователя

- При запуске Ollivo тихо проверяет обновления, если это разрешено в настройках.
  Нашлось — сверху появляется полоска «Есть версия …».
- «Настройки → Обновления Ollivo»: переключатель автопроверки, выбор канала,
  «Проверить сейчас», прогресс загрузки. После установки программа перезапускается сама.
- Автопроверка выключена — Ollivo не выходит в интернет без просьбы.

## Выпуск на GitHub

После публикации в stable — тег с версией:

```bash
git tag v0.1.0
```

```bash
git push origin v0.1.0
```

Workflow `release.yml` берёт из S3 тот же установщик, что раздаёт автообновление, и создаёт
GitHub Release: текст — `release-notes/<версия>.md`, ниже — SHA256 и как пройти SmartScreen.
Сайт сам начинает вести кнопку «Скачать» на этот установщик.

## Проверка обновления

`update::tests::published_update_real` (`--ignored`) скачивает `latest-beta.json` и установщик из S3
и сверяет подпись с ключом в `tauri.conf.json` — так видно, что выложенное обновление встанет.
